# Anvil 五分钟演示

## 演示前

1. 在同一终端执行 `.\start.ps1 -Doctor`，确认模型、依赖和权重全部就绪。
2. 使用 `python anvil.py --prepare-demo --image <公交车图片>` 生成沙箱。若文件已实现，使用新副本或还原演示任务代码，不要在现场重置真实项目。
3. `.\start.ps1`，打开 `/console` 并粘贴 `.runtime/service-token`。先跑通一次真实验收，保留报告作备用；模型加载和冷启动耗时与机器有关。

## 0:00—0:40：定位与结构

“给本地小模型一张单文件 Python 工单；它选择受控工具，框架验证，不以模型声称完成为准。记忆和视觉是同进程模块，共用配置与审计。”

展示模块就绪状态和 README 架构图。代码模型、视觉模型、嵌入模型的职责分开说明。

## 0:40—2:10：代码修改与人确认

点击演示①、创建工单。展示 recon → edit → 三道 gate。待确认时查看 diff，展示真实文件仍未修改，再点确认落盘。

如现场模型运行超过预计时间，展示已保存的真实报告和工单记录；不要将回放或离线替身冒充现场推理。

## 2:10—3:10：项目记忆闭环

确认演示①后等待 `memory_ingested` 记录；点击演示③。打开本单接入记录，定位 `hr_retrieve` 的命中内容和 `context` 中实际进入模型的记忆。

强调“另一项目不召回此项目记忆；未确认或拒绝修改不写入成功经验”。

## 3:10—4:20：真实视觉与工具授权

点击演示②，展示工单声明 `visual_tasks`，然后在记录中展示 `visual_query`、原图摘要、SVSG 断言和复审状态。图片像素确实送入视觉模型；低置信区域另做一次看图复核。若返回 `delivered_with_review`，明确说明哪些内容仍需人审。

当前视觉契约适合检测器支持的物体、计数和空间关系；不要用任意报错截图 OCR 作为已经完成的能力演示。

## 4:20—5:00：故障与可复现性

展示集成测试中的故障注入记录：错误补丁被 gate 拒绝，下一轮携带反馈修复；记忆写入失败保留待入库文件，恢复后重试。指出一条端到端验收命令、报告位置、调用和输出上限、真实 token 与耗时记录。

提交仓库链接、README 和演示工单记录。无第三方 MCP；源码来源与许可证说明见 `vendor/`。
