# 考核材料总览

Anvil 以「本地大模型编码 Agent 工程」申报：把“修改一个 Python 文件”变成受控工单——本地模型提出修改，程序完成上下文组装、工具执行与三道验证（语法 → 静态规则 → 测试），人工确认后落盘。项目记忆（HR）与结构化视觉（SVSG）内嵌于同一进程，是扩展能力。

## 三项材料对照

| 考核项 | 文档 | 现场可跑的验证 |
|---|---|---|
| AI 基础理论学习 | [理论与实现](理论与实现.md)：原理与实现的对应、公式、三个可复现实验、答辩自测 | 文中三条 unittest 命令 |
| 大模型工程开发 | [工程说明与演示](工程说明与演示.md)、根 [README](../../README.md)：架构、设计取舍、五分钟演示 | `python scripts/assess.py --live --scope code` |
| 资产复用性 | [部署与发布](部署与发布.md)：新环境安装、依赖锁、CI 配置、发布与回退 | 新目录按文档从零安装并跑通 |

## 建议的审阅路线

1. 先读本文件与根 README，了解项目做什么、怎么跑。
2. 看[工程说明与演示](工程说明与演示.md)的架构图与五分钟演示脚本。
3. 有条件时按[部署与发布](部署与发布.md)在新目录安装，运行 `scripts/integration_e2e.py --scope code` 看真实链路。

## 验收命令

| 命令 | 内容 |
|---|---|
| `python anvil.py --doctor --scope code` | 依赖、Ollama 与代码模型就绪检查 |
| `python scripts/selftest.py --core` | 离线回归（替身输出，不调模型） |
| `python scripts/integration_e2e.py --scope code` | 真实 HTTP + 本地模型的完整代码链 |
| `python scripts/assess.py --live --scope code` | 汇总以上检查，生成源码包与验收报告 |

`scope` 说明：`code` 覆盖代码主线；`memory`、`full` 分别加入记忆与视觉，需要额外准备嵌入模型、视觉模型和 YOLO 权重（见[部署与发布](部署与发布.md)）。

## 补充资料

- 工程过程文档：`docs/` 下的架构审查、运行时优化与适配验收记录。
- 内嵌组件来源：HR/SVSG 快照、提交版本与源文件哈希在 `vendor/manifest.json`，许可证见 `vendor/NOTICE.md`。
- 持续集成：`.github/workflows/assessment.yml`（GitHub Actions）与 `azure-pipelines.yml`（Azure DevOps）两套流水线配置，运行离线验收并产出源码包。
