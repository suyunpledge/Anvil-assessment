# Anvil 考核提交入口

Anvil 以**本地大模型编码 Agent 工程**申报第二项：将单文件 Python 修改任务转成受控工具调用，经程序验证、人工确认后落盘。项目记忆和结构化视觉是扩展能力。无需再制作短剧视频来重复满足“或”关系。

用户提供的三项合计 **75 分**；其余分值及官方细分标准尚未提供。下表是证据组织方式，不是评分承诺。

| 考核项 | 分值 | 可审阅材料 | 可操作证据 | 尚需本人/平台完成 |
|---|---:|---|---|---|
| AI 基础理论学习情况 | 25 | [理论与实现](理论与实现.md)：原理、取舍、代码定位、答辩题 | 用故障注入、上下文回退、项目隔离实验解释原理 | 本人填写真实学习记录并完成口述/实操；文档不能替代学习证明 |
| 大模型工程或工作流开发 | 25 | [工程说明与演示](工程说明与演示.md)、根 README、状态机契约 | `scripts/assess.py --live --scope code`；真实 HTTP、模型、gate、确认、独立边界用例 | 使用本次报告说明范围；不能把替身测试当模型效果 |
| 资产复用性 | 25 | [部署与发布](部署与发布.md)、依赖锁、两套 CI、源码包清单 | 全新目录安装、ZIP 校验、同任务验收；报告记录模型 digest、源码哈希、环境 | 将审阅后的分支和产物上传平台，补流水线地址、固定版本及第三方复现记录 |

## 推荐交付目录

运行 `python scripts/assess.py --live --scope code` 后，将输出目录中的 `publish/` 作为评审附件：

```text
publish/
  Anvil-assessment.zip          # 源码、文档、部署脚本、依赖锁、CI；无模型及运行目录
  Anvil-assessment.zip.sha256   # 压缩包摘要
  offline.json                 # 每组离线检查结果及 skip 摘要
  summary.json                 # 环境、源码哈希、模型 digest、真实结果、用量
  assessment.md                # 人类可读验收摘要
```

`publish/` 不包含令牌、原始提示词和整个 `.runtime/`。完整演示记录在同次运行的 `live/`；如评委需要，可仅分享此次合成演示的记录。失败运行也会生成报告，提交前必须看 `ok` 和所有步骤结果。

## 提交前核对

- [ ] 理论材料中的个人学习记录已按事实填写，可以现场解释至少一个成功案例和一个失败案例。
- [ ] `summary.json` 的 `live_requested` 为 `true`，`steps.live.ok` 和总 `ok` 为 `true`。
- [ ] 明确本次范围是 `code`、`memory` 还是 `full`，报告中未测试能力不写成已完成。
- [ ] 资产仓库包含实际交付源码，不能只链接一个未更新的旧分支；提交 SHA 与交付包文件哈希可追溯。
- [ ] 发布页面或流水线包含部署文档和 ZIP 附件，评委账号可访问；保存流水线 URL 和产物摘要。
- [ ] 接收方使用新目录/环境复现，并记录系统、Python、模型 digest、命令、结果及差异。

## 发布登记（完成后填写）

| 字段 | 记录 |
|---|---|
| 平台 / 仓库地址 | 待填写；当前本地 remote 为 `suyunpledge/Anvil` |

| ZIP SHA-256 | 从交付包旁的 `.sha256` 文件复制 |
