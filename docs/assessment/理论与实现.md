# AI 基础理论与 Anvil 实现

本文是学习和答辩材料，不代表个人已经完成课程或获得认证。下面的原理、实验和问题用于说明“懂原理，并能解释工程取舍”。

## 1. 从模型原理到工程控制

| 知识点 | 应掌握的原理 | 在 Anvil 中如何体现 | 可定位实现 |
|---|---|---|---|
| 机器学习与泛化 | 训练学习参数，推理用固定参数计算；训练集成功不等于未见任务成功 | 当前验收固定样本用于链路检查，不对外宣称通用编程成功率 | `scripts/integration_e2e.py`；历史基准仅供参考 |
| 自回归语言模型 | 文本先分词，再逐 token 预测；序列概率为各条件概率的乘积 | 输出 token、调用次数、超时分别受约束；模型说“完成”不作为结果 | `anvil.toml`、`integration/models.py` |
| Transformer | 注意力按 Q/K 相似程度加权 V；位置信息补充顺序信息 | 调用已有模型进行推理，Anvil 本身不实现 Transformer 训练 | 模型适配层、下文原始论文 |
| 上下文窗口 | 输入、工具定义、历史与输出预算共同占用上下文；窗口大小不是长期记忆 | AST 切块、符号引用、项目记忆与预算裁剪；小文件回退全文 | `context/builder.py`、`core/statemachine/engine.py` |
| 采样与复现 | 低温度减少采样波动，但不能保证跨硬件、运行时逐字相同 | 固定任务和模型摘要，以可观察行为/测试结果定义复现 | 配置、报告 `models.*.digest`、三道 gate |
| Embedding 与相似度 | 嵌入把文本映射到向量；余弦相似度比较方向，不保证事实正确 | 检查维度、非有限值和零向量后归一化，按项目检索 | `integration/memory.py::Embedding` |
| RAG | 在推理时检索外部资料并加入上下文；检索命中还必须真正进入提示词 | 已确认工单 → outbox → HR → 下张单上下文；项目路径哈希隔离 | `integration/memory.py`、`context/hr_bridge.py` |
| Prompt / 工具调用 | 工具定义只是模型的可选输出契约，实际执行须由宿主验证 | recon 只读；补丁目标、视觉授权和路径在执行端再次检查 | `core/statemachine/tools.py`、`context/visual_tools.py` |
| Agent 与工作流 | Agent 决定受控动作，工作流定义状态、验证、重试和终止 | recon → edit → gate → confirm；失败反馈重试，预算耗尽转人审 | `core/statemachine/engine.py`、`service/runner.py` |
| 幻觉与验证 | 语言流畅、置信度高都不是事实证明；验证必须对应业务要求 | 语法、名称/注解/保留性、测试分层验证；视觉断言要求结构化锚定 | `core/statemachine/gates.py`、`integration/vision.py` |
| 量化与资源 | 更低位宽降低权重存储/带宽需求，可能影响质量；运行内存还包含 KV cache 等 | 模型选择依赖实际硬件测量，不能只按参数量保证延迟 | 模型 digest、实际 token/耗时记录 |
| 微调与 LoRA | 微调改变参数；LoRA 冻结主权重并训练低秩增量。RAG 不更新模型权重 | 本次默认使用基础 Ollama 模型；仓库另有训练脚本，需单独验证数据和结果 | `scripts/train_qwen_coder.py`、`scripts/qwen_training_data.py` |

关键公式及解释：

- 自回归：`P(x₁…xₙ) = ∏ P(xₜ | x₁…xₜ₋₁)`。生成是条件预测，因此需要外部约束与验证。
- 注意力：`Attention(Q,K,V) = softmax(QKᵀ / √dₖ)V`。经典注意力矩阵随序列长度平方增长；具体模型可能采用不同的实现优化。[Transformer 原始论文](https://arxiv.org/abs/1706.03762)
- 余弦：`cos(a,b) = (a·b)/(‖a‖‖b‖)`。归一化之后可用内积比较方向，但阈值要随模型、语料重新校准。Anvil 的记忆是工程化检索增强；并非重新训练原论文的 RAG 模型。[RAG 原始论文](https://arxiv.org/abs/2005.11401)
- LoRA：`W' = W + (α/r)BA`，`A∈R^(r×k)`、`B∈R^(d×r)`；训练低秩增量可减少可训练参数。不能据此断言本项目已有可靠的领域微调收益。[LoRA 原始论文](https://arxiv.org/abs/2106.09685)
- 权重存储粗估：`参数量 × 位宽 / 8`。例如 7B 的 4-bit 权重理论约 3.5 GB，未计量化元数据、KV cache、计算缓存和运行时开销，不能当作最低显存承诺。

## 2. 三个可复现实验

在仓库根目录、已安装 `test` 依赖的环境中运行：

```powershell
.\.venv\Scripts\python.exe -m unittest integration.tests.test_integration.IntegrationTests.test_gate_failure_repair_is_logged_and_reproducible -v
.\.venv\Scripts\python.exe -m unittest integration.tests.test_integration.IntegrationTests.test_short_file_retains_memory_after_full_source_fallback -v
.\.venv\Scripts\python.exe -m unittest integration.tests.test_integration.IntegrationTests.test_hr_real_storage_project_isolation_and_cache -v
```

1. **故障反馈**：第一次故意输出语法错误，观察 gate 拒绝；修复后再次验证。解释模型产生候选、确定性程序判定的职责分工。这里使用替身输出，证明状态机故障路径，不证明模型自行修错能力。
2. **上下文回退**：检索内容比原文件还大时回退全文，但保持记忆。说明优化必须验证收益和边界条件，“召回成功”和“进入模型上下文”是不同环节。
3. **记忆隔离**：用真实 HR 存储和确定性嵌入替身验证项目隔离、去重/缓存。说明相似度不等于授权，项目身份要在检索前约束。

真正调用模型的实验另执行 `python scripts/assess.py --live --scope code`。若分析记忆收益，需要准备嵌入模型，并用同一批任务做启用/禁用 HR 的对照；当前固定演示不能据以宣称准确率提升多少。

## 3. 答辩自测

| 问题 | 回答应包含的要点 |
|---|---|
| 为什么模型回答“已完成”还不能直接写文件？ | 文本不是执行事实；工具授权、版本一致性、gate、人工确认分别承担不同职责。 |
| RAG 和微调分别解决什么？ | RAG 接入可更新、可追溯资料；微调改变参数行为，需要训练数据、验证集和独立评估。 |
| 召回了正确资料为什么仍可能失败？ | 被预算裁掉、提示未包含、检索过期、模型误用；需检查真实 `context` 记录。 |
| 三道 gate 是否等于代码绝对正确？ | 语法仅解析；类型 gate 是有限静态规则；测试只覆盖用例，均不证明全部行为。 |
| 只跑一次能否报告成功率？ | 只能报告该次案例成功。泛化评估需固定任务集、多次独立运行、失败保留和统计区间。 |
| 为什么固定模型名还不够复现？ | tag 可能更新；还要记录 digest、配置、依赖、源码、硬件与输入。 |
| temperature=0 是否必然输出相同字节？ | 不应保证；硬件、内核与模型版本仍会影响结果，按行为标准比较。 |
| 本地运行是否就完全安全？ | 本地也有越权文件/网络访问风险；Job Object 主要管进程资源，不等于完整网络/文件隔离。 |
| “无 API 账单”是否等于零成本？ | 还有硬件、电力、维护、时延及失败返工；报告实际 token 和耗时。 |
| 视觉模型与同模型复核是否独立交叉验证？ | 不是；相关错误仍可能重复出现，结构化证据和人审仍有必要。 |
